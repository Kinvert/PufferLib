## Target and acceptance

Build a small reusable encoder that consumes real rendered game frames at
human-visible resolutions and reduces them to compact features for PufferLib.
The reference input is the actual scene, typically around640x480 with its natural
aspect ratio. Lower internal resolution is allowed and is the point of the
compression research; reliance on tiny original sprite art or simulator object
IDs is not the main solution. Keep human display, source frame and model input
separately recorded and inspectable.

Success means a repeatable improvement in a useful part of return versus total
training-time curves, without severe hidden per-game regressions. It need not
dominate IMPALA at every accuracy or budget. A useful clean PufferLib encoder,
plus a defensible paper and reproducible research tool, is the delivery target.
This plan cannot promise novelty, SOTA or a multiplier before measurements.

## 1. Make the input and measurement contracts explicit

**Deliver:** one versioned preprocessing/encoder manifest shared by training,
checkpoint restore, evaluator, metadata and reports.

Record raw H/W/channels/layout/range; crop/view and geometry; resize/filter,
padding/alignment; output grid/token shape; encoder hash/version; precision;
frozen/trainable parameter partition; initialization source and data split.
An INI is the user interface; existing static dimensions may initially require
separate captured binaries for different shapes. Do not claim dynamic-size support
until the native shape and checkpoint paths actually implement it.

Maintain two comparison tracks:

- **Encoder isolation:** identical preprocessing, learner, raw observations,
  actions, decisions, seed/world assignment and core. Architecture alone varies.
- **Complete visual system:** same raw frames/game/information access; each
  declared encoder/preprocessor may compress differently, and all its processing
  and pretraining costs count. This is the main backbone/compression question.

Include an efficient practical Nature pipeline with declared resizing, not just
an unmodified giant flatten layer at640x480. Preserve the current full-resolution
reference too when it fits. A smaller-input system winning is not automatically
proof of a better convolution operator.

**Acceptance:** restore rejects an incompatible preprocessing/backbone manifest;
raw source-frame/action/RNG parity holds across policies; evaluator includes
preprocessing inference. Geometry and gaze access cannot differ silently.

## 2. Establish the cost floor and information floor

Before allocating another18-axis campaign, measure one scratch candidate and
Nature with the existing validated paths. Profile actual rollout and learner
batches, CPU environment/raster work, input copies, packing, convolution,
recurrence, optimizer and evaluation startup. Read shared profiling instructions;
if CUDA capture is broken, retain that failure and use native event timers plus
repeated **unprofiled** full-process timing. Never present host/NVTX spans as
GPU kernel time or sum overlapping spans into end-to-end duration.

Prepare full-frame probes for small objects, lookalikes, color distinctions,
motion, edge clipping and subpixel/stride phase. Current games can supply
controlled frames without inventing hidden input features. This small deterministic
test corpus is distinct from a large pretraining dataset and should be versioned.
No dataset is generated by this document.

Compare fixed area resize, learned strided reduction and a detail-preserving
candidate at explicitly chosen internal budgets. Use full source images in all
cases. Pixel collisions are a rejection signal for required distinctions;
probe accuracy is a diagnostic; actual RL is the final usefulness test.

**Acceptance:** measured per-stage/whole-process costs with GPU exclusivity,
preserved weak results, and a record of which visual distinctions disappear.
Report input bytes and feature bytes independently from MACs and SPS.

## 3. Build a small full-frame family, not every possible operator

First candidate panels should answer architectural questions at fixed topology:

| Panel | Change | Keep fixed |
|---|---|---|
|Dense compression stem|Stage stride/width and compact spatial readout|ReLU, learner/core, raw frames, initialization|
|Narrow bottleneck|Low-resolution channel mixing versus plain dense stages|Approximate measured runtime envelope and input contract|
|Spatial detail|Uniform grid versus coarse/detail representation|Total observed frame, action/gaze interface and cost accounting|
|Activation/readout|ReLU versus qualified SiLU/PReLU; flatten versus spatial pooling|Surviving stem and training recipe|

A proposed first full-frame grid uses two or three stages with narrow early
channels and explicit spatial output. Avoid per-pixel large channel expansion.
Latent width and spatial resolution are separate coordinates. Start with no more
than4–6 active architecture axes in a panel; broaden only after coverage and cost
show the need. These are experimental choices, not new current INI keys.

Reuse Flex2's implemented dilation, learned activations and spatial readout after
its required GPU qualification and new sprite/full-frame integration. SwiGLU
requires two projected branches, not an activation ID pretending SiLU is gating.
Grouped/depthwise/partial convolutions deserve a measured operator panel before
long RL: fewer MACs can still be slower at small channels. Preserve cheap dense
controls. Do not reimplement features already present in Flex2 without reason.

**Acceptance:** independent forward/parameter/input-gradient checks at actual
batch/shape/precision, signed and near-boundary cases, memory checks, exact
repeatability on the pinned stack, and checkpoint/reload/short-learning checks.
Existing smooth-positive/zero sprite cases do not prove arbitrary new branches.
New kernels need fixed tolerances and preserved failures, not relaxed thresholds
after seeing a failure.

## 4. Train one small backbone before building a giant pretraining system

**Deliver first:** a bounded, versioned collector/export design and native
encoder-only import/export. Follow the existing pixel-coordinate label plan.
For full scenes, vary objects' visible location, size, overlap, background and
animation through actual renderer transformations. Include rare lookalikes and
small objects. Never use invisible state as a target identifiable from one image.

Before creating data, declare training/validation splits by trajectories, assets
and games. Entire games reserved for transfer cannot enter pretraining, teacher
selection or architecture tuning. Adjacent frames and the same sprite recolored
across splits are weak independence. Existing all-game results are development
evidence; relabeling already-seen games as untouched does not create a test set.

On a single chosen tiny encoder compare:

1. Scratch end-to-end control.
2. Visible-object/detail pretraining, then end-to-end adaptation.
3. The same pretrained prefix frozen, with a trainable adapter/core.
4. Reconstruction pretraining control on the same data/graph.

Add temporal pretraining as a separate matched objective panel, then optional
teacher distillation if simple supervision is inadequate. A frozen-random control
helps diagnose whether pretrained features matter. A large teacher stays offline;
its training/inference costs and data remain in the accounting. Do not download
ImageNet or large models as a prerequisite for the first native implementation.

**Acceptance:** fixed architecture parity across initializations, validated
pixel-aligned labels and weights, useful held-out probes, followed by downstream
curves. Reconstructed pictures or high classification accuracy alone do not pass.

## 5. Implement frozen-feature reuse only after the representation works

Integrate an explicit frozen prefix before the trainable adapter/core. Compute
features at rollout, retain them with sequence/RNG/termination metadata, and
bypass the frozen prefix during learner replay. Preserve actual behavior logits
and recurrent starting state semantics. Hash-bind buffers and checkpoints to
preprocessing and encoder version. Keep an uncached reference path.

**Acceptance:** cached versus recomputed frozen features agree, frozen weights
never mutate, replay/eval results and policy gradients agree within the declared
numerical contract, and measured memory/time improves on the complete learner.
No latent cache may silently survive encoder updates. Account for new feature
copies and any reconstruction/teacher work still executed during RL.

Atlas memoization and repeated-tile execution may later be useful specialized
backends. They must have separate labels, RGB-equivalence tests and uncached
full-image controls; neither is the foundation of the general-game claim.

## 6. Improve search efficiency without sweeping seeds

Version the next feedback protocol instead of silently changing old18-coordinate
ledgers. Record effective operation graphs and inactive axes. Detect duplicates
before expensive execution, retain their proposal records, and predeclare whether
they reuse identical deterministic evidence or run as deliberate timing repeats.
Do not count reused results as new independent replicas.

Keep seven fixed training seeds7/42/69/123/173/2027/9001 for confirmation.
For discovery, a declared smaller fixed prefix of those seeds can screen candidates,
followed by the same expansion for every promoted model. This is a **proposed
change**, not the current seven-seed campaign. Never sweep or select seeds.
Use separate fixed evaluation worlds and untouched final tests. Adaptive
promotion/early stopping must retain all failures and incomplete curves, and
cannot be called equal-budget confirmation.

Prefer all development games with fewer early replicas to selecting only easy
games. Fixed common per-game learners stay outside architecture search. Calibrate
useful learning budgets before discovery;1Mi decisions is not automatically enough
for a new full-frame representation just because the tile pilot learned.

For full-frontier discovery, save roughly8 scheduled checkpoints and define a
curve utility in advance. One implementable choice is mean per-game area under
the normalized score curve on a fixed log-time grid, using only the latest
checkpoint available at each time. Define the pre-first-checkpoint value through
an initial evaluation, and mark budgets not covered by a completed run as missing;
do not extrapolate successful learning. Keep endpoint score/cost and all per-game
curves visible. Apply a predeclared worst-game/regression check for promotion so
average gains cannot hide collapse. A scalar is a search heuristic, not the paper's
entire Pareto result. Do not manufacture independent observations from checkpoints.

**Acceptance:** synthetic accounting tests plus actual bounded multi-game feedback
canary for the changed protocol, explicit GP replay, cost counted once, all
assignments present, and duplicate/failure semantics audited. Reuse historical
proof for unchanged paths; do not restart completed allocations.

## 7. Budget an overnight run from measured complete-panel costs

Measure validation, training, all checkpoint/skin evaluations, process startup,
reporting and storage—not trainingSPS alone. Set a deadline reserve before starting
each complete candidate. If a candidate cannot fit, stop at a clean boundary
while preserving every prior observation. Later continuation must import an
audited prefix explicitly; never overwrite failed parent status.

Amortize repeated evaluator process/model startup where practical, but prove
episode-ID/policy-RNG independence from order, batch size and episode length.
Every requested episode must finish or be explicitly censored/missing. Do not
favor early finishers. Allocate enough baseline time to have useful controls,
but do not assume slow controls plus24 all-game/seven-seed trials fit12hours.

5090 handoff will require a new committed, tested preparation/run command and
Markdown instructions after these implementations are ready. This file is a
plan, not a command for the remote agent to execute now.

## 8. Paper and clean delivery

Freeze selected architectures, preprocessing and initialization before testing.
Compare Nature/IMPALA/Impoola using competent native implementations and give
baselines the same preprocessing/pretraining opportunity where relevant. Separate
architecture, initialization, compression and backend ablations. Report task
quality versus decisions, downstream training time, total pretraining-inclusive
time, inference latency, peak memory and repeated unprofiled SPS.

Use paired training replicas and fixed eval worlds; quantify uncertainty over
training seeds as well as evaluation episodes. Checkpoints from one run and
skins sharing worlds are correlated. Retain all declines, missing runs and
negative transfer. Define the frontier claim and its uncertainty before looking
at confirmation results. Show each game as well as a declared aggregate.

Only then extract the selected encoder and necessary minimal interfaces into a
clean native PufferLib PR. Experimental search, annotation and diagnostics stay
separate from simple game C code. A system that finds useful architectures can
be a valuable deliverable even if no universal CNN wins.
